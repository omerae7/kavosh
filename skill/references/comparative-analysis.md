# Comparative Analysis

## Define the Comparison

Specify the decision objective, options, criteria, and use context. If user preference is decisive, activate the User Context Advocate and ask only about material ambiguity.

## Align the Options

Check the following before comparing:

- model and version;
- date and product or data generation;
- country, market, and currency;
- configuration and feature scope;
- test or use conditions;
- contract or ownership period;
- taxes, ancillary costs, and lifecycle cost when relevant;
- and a shared definition of every criterion.

Do not perform a misaligned comparison without explicitly stating the limitation.

## Criteria

Derive criteria from the user's objective and the nature of the problem. Examples include:

- performance and quality;
- price and total cost;
- reliability;
- ease of implementation or use;
- compatibility and constraints;
- support and maintenance;
- risk and reversibility;
- useful life and future readiness.

Do not invent a score for a criterion that lacks data. Record **insufficient data** instead.

## Weighting

Take criterion weights only from the user's explicit preferences, the problem's requirements, or a disclosed method. Do not present arbitrary weights as user preferences. If weights are unknown and the result depends on them, show the choice thresholds or ask the necessary question.

## Conclusion

For each option, state its relative strengths, relative weaknesses, conditions of suitability, and principal tradeoff. When the choice depends on priorities or circumstances, explain which option is better for which user or condition instead of declaring an absolute winner.

Use a table only when it clarifies shared criteria more quickly. Do not give asymmetric or promotional data the same weight as independent evidence.
